# InstallButton.tsx + useInstallPrompt.ts

## Назначение
Установка PWA «Спецтехника» как настоящего Android-приложения (WebAPK).
Решает проблему «открывается как сайт»: современный Chrome на Android НЕ
показывает авто-баннер установки — приложение должно само поймать событие
`beforeinstallprompt` и показать кнопку. Без этого пользователь максимум
делает ярлык-закладку («Добавить на главный экран»), который открывается
в браузере.

## Состав
- `src/hooks/useInstallPrompt.ts` — логика: ловит `beforeinstallprompt` и
  `appinstalled`, детектит standalone (уже установлено) и iOS. Отдаёт
  `{ canInstall, isStandalone, isIOS, installed, promptInstall }`.
- `src/components/pwa/InstallButton.tsx` — UI. Встроен в `LoginPage` (экран
  входа, единственный публичный экран — до авторизации).

## Поведение по платформам
| Ситуация | Что показывается |
|---|---|
| Уже установлено (standalone) | ничего |
| Android/Chromium, событие пришло | кнопка «📲 Установить приложение» → системный диалог |
| iOS Safari | текст «Поделиться → На экран „Домой"» (программной установки нет) |
| Chromium, событие ещё не пришло | тихая подсказка про меню ⋮ (закрываемая) |

## Важно
- `prompt()` вызывается только внутри клика (требование браузера).
- Повторно `prompt()` на том же событии нельзя — после показа сбрасываем.
- **В dev (`npm run dev`) настоящая кнопка НЕ появится**: SW отключён
  (`devOptions.enabled:false` в vite.config.ts), а без SW Chrome не шлёт
  `beforeinstallprompt`. Виден только fallback-хинт. Проверять реальную
  кнопку — на проде https://kip.dkbikonstrykt.ru/ с телефона.

## История изменений
- **2026-06-15** — создан. Причина: на пилоте приложение открывалось как
  сайт. Аудит (4 агента) подтвердил: технически установимость в порядке
  (манифест/иконки/SW/HTTPS), не хватало только обработчика
  `beforeinstallprompt`. Параллельно добавлен явный `purpose:'any'` иконкам
  192/512 в vite.config.ts.
